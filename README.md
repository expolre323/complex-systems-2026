## 四、后续作业怎么加（重要）

新增一次作业分三步，**不需要改动已有页面**：

1. **加页面**：复制 `a2.html` 为 `a3.html`，替换章节内容；样式与脚本路径不变。
2. **加数据**：新建 `assets/js/a3-data.js`，在文件末尾挂到共用命名空间
   ```js
   window.CSE = window.CSE || {};
   window.CSE.a3 = { /* 本次作业的数据 */ };
   ```
   并在页面里按 `data.js → a3-data.js → fx.js → a3.js` 的顺序引入。
3. **改状态**：把 `data.js → roadmap` 中该条目改为
   ```js
   { no: '03', ..., status: 'published', date: '2026.12.xx', href: 'a3.html' }
   ```
   首页的序列条目会立刻从虚线"预留位"变成实线"已发布 + 进入作业"，顶部的进度条、进度环与统计同步更新。

> 首页只做索引，不做内容堆叠：**一次作业一个 URL**。这样单次成果可以直接发给老师，也不会因为后续补充把前面的结论改得对不上。

## 五、发布到 GitHub Pages

```bash
git init
git add .
git commit -m "CSE 2026 作业序列：轮腿式无人作战平台"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后仓库 **Settings → Pages**：Source 选 `Deploy from a branch`，分支 `main`，目录 `/ (root)`，保存。

约 1 分钟后访问 `https://<用户名>.github.io/<仓库名>/`。

> 若仓库名就叫 `<用户名>.github.io`，则直接是 `https://<用户名>.github.io/`。

## 七、内容口径

- 所有质量、功率、速率、指标均为**课程概念设计目标**，用于演示"分解—分配—闭合"的方法，不代表任何在研或在役装备的真实参数。
- 作业 02 的两份文档按 **ISO/IEC/IEEE 29148:2018** 的 BRS / StRS 范例轮廓（郭宝柱书表 4-1、表 4-5）组织章节；相关方清单按该章"直接相关方 / 生命周期交互与使能系统 / 施加影响与被影响"三分法抽象为 18 类，矩阵按表 4-3 的列项填写。
- 需求条目全部使用"应（shall）"句式，每条只表达一个需求，标注优先级（必须 / 应该 / 可能）与主验证方法（T 试验 / A 分析 / D 演示 / I 检查），并给出相关方来源与追溯目标。
- 平台代号 **IBEX-01** 为小组概念编号，无其他命名含义。
- 涉及效应的部分明确写为"目标指示与效应交接"，杀伤决策始终由授权人员作出，与课堂强调的安全边界一致。
