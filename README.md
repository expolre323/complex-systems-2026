| 04 运营概念 ConOps | 组织层多对多：三阶段 × 五角色运行节拍表、角色职责、5 条运行假设、4 条 What-if | 3 阶段 |

## 四、改内容时改哪里

**文字与数据都在 `assets/js/` 的三个数据文件里，页面结构不用动。**

| 想改的东西 | 改这里 |
|---|---|
| 质量 / 功率 / 信息流预算的分配值 | `data.js → budget`（`rows[].kg` / `.kw` / `.rate`），页面上的柱条与合计会自动重算 |
| 11 个系统的职责、指标、接口 | `data.js → systems` |
| 40 条需求的内容、优先级、验证方法、来源 | `a2-data.js → reqs.items` |
| 相关方的坐标（决定四象限里的位置） | `a2-data.js → stake.groups[].items[].pw / .it` |
| 业务需求、任务需求、场景、状态 | `a2-data.js → biz` / `opscon` |
| 41 条系统需求、分配、验证方法 | `a3-data.js → syr.items` |
| 控制动作与反馈（框图下方的表） | `a3-data.js → arch.ca`；框图本身在 `a3.html` 的 `#cscSvg` 里，改坐标即可 |
| UCA、致因场景、安全需求 | `a3-data.js → stpa.uca` / `stpa.causes` / `sr.items` |
| 追溯链与自检 | `a3-data.js → trace.chain` / `trace.checks` |
| 首页三张卡的标题、要点、日期 | `data.js → roadmap`（`q` 是那张卡上的「核心问题」，`keys` 是三条要点） |

改完刷新即可，没有任何构建步骤。

### 如果老师又加了第四次作业

1. 复制 `a3.html` 为 `a4.html`，替换章节内容（`#cscSvg` 若不需要可整段删掉），样式与脚本路径不变；
2. 新建 `assets/js/a4-data.js`，末尾写 `window.CSE.a4 = { /* 数据 */ }`，页面按 `data.js → a4-data.js → fx.js → a4.js` 的顺序引入；
3. 在 `data.js → roadmap` 数组里追加一条 `{ no: '04', name: …, href: 'a4.html', status: 'published', q: …, keys: [...] }`，首页会自动长出第四张卡（`.gates` 是等宽网格，四张卡会自动排成 2×2）。

## 七、内容口径

- 所有质量、功率、速率、指标均为**课程概念设计目标**，用于演示"分解—分配—闭合"的方法，不代表任何在研或在役装备的真实参数。
- 作业 02 的两份文档按 **ISO/IEC/IEEE 29148:2018** 的 BRS / StRS 范例轮廓（郭宝柱书表 4-1、表 4-5）组织章节；相关方清单按该章"直接相关方 / 生命周期交互与使能系统 / 施加影响与被影响"三分法抽象为 18 类，矩阵按表 4-3 的列项填写。
- 需求条目全部使用"应（shall）"句式，每条只表达一个需求，标注优先级（必须 / 应该 / 可能）与主验证方法（T 试验 / A 分析 / D 演示 / I 检查），并给出相关方来源与追溯目标。
